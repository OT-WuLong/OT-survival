# OT 生存包数值说明

本文统一记录完整版与适配版 **1.0.0** 的四项状态数值、面板和命令。下面的通用数值表按完整版列出，适配版仅以“适配版差异”一节覆盖例外，其余规则相同。源码目录与构建命令见 [README](../README.md).

## 安装与运行

完整版安装文件是 [OTSurvivalStatus.mcaddon](ot_survival_status/OTSurvivalStatus.mcaddon)，最低游戏版本 **1.26.50**，依赖稳定版 `@minecraft/server 2.10.0`、`@minecraft/server-ui 2.2.0`。

适配版安装文件是 [OTSurvivalStatusCompat.mcaddon](ot_survival_status_compat/OTSurvivalStatusCompat.mcaddon)，最低游戏版本 **1.21.120**，依赖稳定版 `@minecraft/server 2.3.0`、`@minecraft/server-ui 2.0.0`。

导入适合游戏版本的安装文件，在世界里同时启用对应行为包和资源包；两版都不要求开启预览版 API 实验。

本包不依赖 OT 通用包。完整版与适配版使用相同的物品标识、计分目标及 HUD，**同一世界只启用其中一套**。[OTSurvivalStatus_AllVersions.mcaddon](ot_survival_status_compat/OTSurvivalStatus_AllVersions.mcaddon) 只是把两套包放进一个安装文件，不会按游戏版本自动选择；旧客户端若拒绝导入合并文件，使用独立适配版安装文件。

四项机制默认开启，仅生存／冒险模式自动变化。创造／旁观模式不自动消耗或承受本包惩罚，管理员仍可调试显示。所有状态范围均为 **0–100**；每名玩家分别保存自己的数值。

| 状态 | 功能名          | 初始及死亡重生值 | 计分目标           |
| ---- | --------------- | ---------------: | ------------------ |
| 体力 | `stamina`     |              100 | `ot_stamina`     |
| 口渴 | `thirst`      |              100 | `ot_thirst`      |
| 温度 | `temperature` |               50 | `ot_temperature` |
| 理智 | `sanity`      |              100 | `ot_sanity`      |

## 面板与位置调整

工作台中用 **6 个普通泥土合成 1 个生存状态面板**，摆成相邻两行、每行三个，每格放泥土；完整版与适配版配方相同。开启配方解锁时，获得普通泥土可解锁此配方。手持面板可在生存或创造模式使用。

也可用命令获取：

```mcfunction
/give @s ot:status_panel
```

普通玩家直接进入自己的位置调整页。操作员看到两个同宽、无齿轮图标的按钮：“状态条开关”管理全世界机制，“调整我的状态条位置”只管理自己的 HUD。开关页在进入和保存时都检查操作员权限，不要求创造模式；关闭页面不保存。

体力、理智分别位于快捷栏左、右两侧，用 96 档填充从上向下耗尽。口渴是温度图标外侧的开口圆环，从开口右端顺时针消退，96 个数值档约有 92 个不同画面；温度用中央五档图标显示。经验等级数字以半字号白字叠在经验条上，不改变经验值。

### 默认位置与可调范围

以下坐标为 HUD 逻辑单位，相对屏幕底部中央锚点，不是屏幕像素。

| 显示       | 桌面居中 HUD 默认坐标 | 携带／居中触控 HUD 默认坐标 |
| ---------- | --------------------- | --------------------------- |
| 体力       | `[-95,-1]`          | `[-105,-1]`               |
| 理智       | `[95,-1]`           | `[105,-1]`                |
| 温度、口渴 | `[0,-32]`           | `[0,-32]`                 |

默认布局读取原版实际 HUD 状态，不识别手机型号，也不动态测量快捷栏宽度。屏幕比例或 GUI 缩放变化后，可能需要重新校准。

六个滑块按顺序为体力左右／上下、理智左右／上下、温度上下、口渴上下。左右相对默认位置 **−100～＋100**，上下 **−75～＋75**，每档 **1**；包含 0 分别有 201、151 个可选值，负数向左／向上。

只有滑块区域滚动，底部恢复默认开关和绿色“保存位置”固定可见。调整后保存并回到游戏查看，没有实时预览；勾选“恢复默认位置（保存后生效）”再保存，会清除六项个人微调。位置设置仅对本人持久生效，更新包不会自动抹掉原有偏移。

### 关闭机制的含义

关闭某项会冻结其数值，隐藏显示，停用该项后续的消耗、恢复、限制及惩罚；不是只隐藏图像。关闭体力会释放本包持有的跳跃限制，关闭温度会停用冷热联动。已施加的短时药效不强行清除，可能自然残留数秒；口渴反胃最多约残留 10 秒。

体力和口渴各自按动作计算，关闭其中一项不会关闭另一项。温度的动作产热及极端温度伤害也不依赖其他状态开关。

## 数值换算

以下按 **20 游戏刻／秒**换算，卡顿时现实时间可能与表中的秒数不同。这是现行规则的集中记录，不是新的调参方案。适配版未列出的规则沿用这里，仅以其差异表覆盖例外。

体力为 **0** 时禁止跳跃；继续尝试冲刺或游泳时，以缓慢 III（`amplifier: 2`）限制速度，每 3 刻刷新 6 刻；装填原版弓／弩时暂不叠加这项反复施加的减速。近战／投射物伤害与方块破坏会被取消，原版弓／弩使用也尝试取消；动作动画仍可能出现。未耗尽时，挥拳判定期间、近战命中后的半秒、挖掘或装填期间暂停恢复；挥空结算后立刻恢复，不触发命中的半秒暂停。耗尽后无效尝试不再阻止恢复，恢复至 **20** 才解除限制。常温下静止从 0 恢复到 20 约 2.5 秒，行走／普通水中活动／滑翔约 5 秒。温度为冷／寒冷时，**仅恢复速度**分别乘 **0.8／0.5**；消耗不变。

| 平时                                 |                                                     −1／20 秒（−1/400 点／刻） |

活动额外失水按“对应消耗 1 体力 ↔ 数值上额外失去 0.025 口渴”制定，**不是读取体力值来算口渴**。体力关闭时口渴照常按动作失水；口渴关闭时体力照常消耗。不同动作相加，同一动作不沿用旧规则重复扣。只有**完成**饮用／进食才结算。温度为热／炎热时，所有失水（基础、活动和攻击瞬时费用）分别乘 **1.25／1.5**，恢复量不变。头部浸水时，持续失水让位于补水。口渴 **<20** 时每 **5 秒**伤害 1 点生命；到 **0** 时改为每 **2 秒**伤害 1 点生命，并每 160 刻刷新一次持续 200 刻的反胃 I。缺水伤害可以致死，补水至 **≥20** 停止后续伤害；已存在的反胃不强制清除。

饮用或进食须完整完成，半途取消不补水；喷溅／滞留药水及普通水桶不算直接饮用。头部浸水补水并不免除原版溺水风险。缺水严重度切换时伤害重新计时，不继承上一档将到期的计时。

|  当前值 | 状态 | 联动                                   |
| ------: | ---- | -------------------------------------- |
|   0–14 | 寒冷 | 体力恢复 ×0.5；理智持续扣除 −2／分钟 |
|  15–34 | 冷   | 体力恢复 ×0.8；理智持续扣除 −1／分钟 |
|  35–65 | 正常 | 无冷热惩罚                             |

| 85–100 | 炎热 | 失水 ×1.5；理智持续扣除 −2／分钟     |

目标始终截在 0–100。未知群系按普通群系处理。火源、天气和装备影响的是**目标或趋近速度**，不瞬间把玩家温度改到目标值。温度 **<15** 或 **≥85** 时，每 **8 秒**伤害 **1 点生命**；寒冷且在水中时改为每 **2 秒**伤害 **1 点**。可致死，离开极端温度后重置伤害计时；创造模式及温度开关关闭时不继续伤害。动作产热与体力、口渴的开关独立。

炎热名单包括沙漠、恶地／`mesa` 系列及热带草原变体；寒冷名单包括冰雪群系、寒冷针叶林、冷海／冻海、冷海滩及相关变体。**丛林与暖海当前仍按普通群系处理**，具体 ID 名单在温度脚本的 `HOT_BIOMES`、`COLD_BIOMES` 中。未列入的群系也按普通目标处理。

湿身余量退出／重进后保留，离线不计干燥时间；死亡重生、关闭温度或切换非生存／冒险模式会清除。动作热量每秒重新结算，不会把上一秒的目标加成永久累积；游泳产热可以减缓失温，但不会免疫冷水。

## 适配版差异

| 项目               | 适配版行为                                                                                                                                 |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 近战               | 确认命中才扣体力 2、口渴 0.05，并暂停体力恢复 10 游戏刻；接触与受伤事件报告同一命中时去重。不能可靠检测挥空，挥空不计费。                  |
| 挖掘               | 实际破坏一个方块扣体力 1、口渴 0.025；没有开始／取消挖掘事件，不按持续时间收费，未挖成不计费。                                             |
| 耗尽后的攻击限制   | 仍禁跳、阻止方块破坏及原版弓／弩使用，并在跑／游泳时限速；缺少伤害发生前的取消事件，不能保证阻止近战或投射物伤害，不可作为战斗防作弊机制。 |
| 温度动作产热       | 挥空、未完成的持续挖掘不产热；确认命中或成功破坏方块各计目标产热＋2。行走、冲刺、游泳及跳跃沿用完整版。                                    |
| 水瓶及普通饮用药水 | 不读取药水内容，所有可饮用`minecraft:potion` 统一补口渴 20；牛奶、四种汤煲及汤煲的升温效果不改，喷溅／滞留药水仍不当作饮用。             |

未列出的玩法、恢复、惩罚、HUD、权限和数值沿用上面的完整版规则。尤其“无法区分药水”只影响 `minecraft:potion`，不是把所有饮用或食用物品都改成同一补水量。

## 命令接口

命令需要世界允许作弊及相应权限。世界开关与个人调试是不同接口，不要混用。

### 命令方块控制全世界开关

```mcfunction
scriptevent ot:status_toggle stamina off
scriptevent ot:status_toggle stamina on
```

把 `stamina` 换成首页表中的其他功能名即可。`on` 开启，`off` 关闭，命令方块和面板共用同一份设置。该接口只接受命令方块来源；旧通用包的 `ot:feature_toggle` 不控制本包。

### 读取状态与显示全部数值

四个计分目标都是实际数值四舍五入后的**只读镜像**。体力／口渴通常每刻同步，温度／理智约每秒同步；创造模式也可读取保存的值。外部修改分数不会反过来改变真实状态，关闭开关后分数保留。

检测体力不高于 20 的玩家：

```mcfunction
execute as @a[scores={ot_stamina=..20}] run title @s actionbar 体力不足
```

开发期在循环命令方块中显示全部数值：

```mcfunction
execute as @a run titleraw @s actionbar {"rawtext":[{"text":"体力 "},{"score":{"name":"@s","objective":"ot_stamina"}},{"text":"  口渴 "},{"score":{"name":"@s","objective":"ot_thirst"}},{"text":"  温度 "},{"score":{"name":"@s","objective":"ot_temperature"}},{"text":"  理智 "},{"score":{"name":"@s","objective":"ot_sanity"}}]}
```

发布时撤掉该命令方块即可。动作栏是共用位置，其他功能发送文字会覆盖它；重复命令方块也应避免每刻向聊天栏发消息。

### 管理员设置自己的测试值

聊天栏示例：

```mcfunction
/scriptevent ot:stamina_test 25
/scriptevent ot:thirst_test 20
/scriptevent ot:temperature_test 50
/scriptevent ot:sanity_test 100
```

四个测试接口都接受 `on`、`off` 或 0–100 整数。`on` 将温度设为 50，其余设为 100；数字直接改变本人实际值，**不是冻结数值或绕过玩法惩罚**。生存／冒险模式仍会继续变化和触发阈值，创造模式只显示测试条。

`off` 只退出个人测试显示，不关闭世界机制；世界开关关闭时，测试也不能显示对应状态。接口仅响应管理员玩家来源，不能用命令方块给普通玩家直接改真实数值。

## 保存 升级与兼容边界

同一套包升级时保留 UUID，已有玩家数值、个人位置与世界开关继续使用原存档。首次启用独立包或切换两版时，尽量从已有的四个计分目标接续当前整数值，世界开关优先读 `ot_status_flags`；未取得数值则采用初始值，未设置的开关默认开启。

不同包 UUID 下的隐藏动态属性无法直接读取，因此旧通用包或另一变体中的湿身、睡眠记录、惊慌冷却不能完整迁移，会重新计时；旧数据本身不被删除。首次读取时若玩家计分身份尚未就绪，会跳过该分数并使用默认值。长期世界在升级或切换前应备份。

本包通过标题消息给 HUD 传值，其他频繁发送 `/title` 的系统，以及同样覆盖 `hud_screen.json` 的资源包可能冲突。天气由变化事件记录：首次装入已在下雨的世界，降水降温和淋雨补水可能要等下一次天气变化才生效。屋顶、透明方块、水浸块及不同 GUI 缩放的边界仍须对应客户端实测。

撤包前宜先关闭体力或让受限玩家恢复。如果撤包后跳跃权限仍被禁，管理员可执行：

```mcfunction
/inputpermission set @s jump enabled
```
